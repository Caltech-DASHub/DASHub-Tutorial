# DAS Hub File Formats

This document describes the main data file formats provided on the DAS Hub.
These files use the HDF5 format, but with different schemas and sometimes
different storage details.  They can be identified relatively easily, simply
by looking for the presence or absence of datasets with specific names.

# General Overview

All files produced by these programs will generally have a string attribute
`dasutil_version` on the root group, set to the version of DAS-Utilities that
created the file.  **Note that this attribute is absent on files created by
earlier versions of DAS-Utilities.**

In general, all files use the ISO-8601 format for representing dates and
times.  If seconds or fractional seconds are absent in a time value then they
should be assumed to be zero.

## Examining HDF5 File Contents

It's easy to manually examine an HDF5 file with the [HDF5 Command-line Tools][hdf5-cmdline]
available on most platforms.  Commands like this can be used to list or dump
attributes on an HDF5 file:

```sh
# List details of all datasets and attributes in an HDF5 file
h5ls -vr path/to/file.h5

# Dump the values of all attributes in an HDF5 file
# Removing the -A will cause the command to dump datasets as well
h5dump -vr -A path/to/file.h5
```

# Processed or Desampled Files

The main file format is usually called a "processed" file, but it may also be
called a "desampled" file in some documentation due to being produced by the
`Desample_DAS.py` program.  Extracted event files may also use this format,
but with extra attributes that hold event details.

These files are continuous recording periods with no internal gaps.  Thus,
they only include a "first sample time" in the metadata.

## The `Data` Dataset and Attributes

The DAS data is held in a dataset named `Data` at the root level of the file.
This is a 2D dataset where one dimension is the spatial dimension (channels)
and the other is the temporal dimension (samples).  The spatial dimension is
usually first, but file-readers may want to compare the dataset's shape to
the attributes below (e.g. `(nCh, nt)` or `(nt, nCh)`) to determine which
dimension is first in the file.

This dataset also defines a number of attributes:

*   `startTime` is an ISO8601-format UTC date/time string of the first sample
    in the file
*   `endTime` is an ISO8601-format UTC date/time string of the last sample in
    the file (equal to `startTime + timedelta(seconds=(nt - 1) / fs)`)

*   `system` is the name of the DAS array (a.k.a. "DAS system") that the
    data was acquired from
*   `processing` is an optional JSON-format string attribute that records
    some processing parameters about the DAS data
*   `unit` is an optional string attribute specifying the units of the data

*   `fs` is the sample rate of the data in samples per second (Hz)
*   `nt` is the number of samples
*   `dt` is 1.0 / `fs`

*   `nCh` is the number of channels
*   `dCh` is the channel spacing in meters
*   `GaugeLength` is the gauge length (may be missing on older files; check
    for a `GaugeLength` attribute on the `/Acquisition_origin` dataset if
    missing)

If the processed file was generated by desampling input data files, the
values of the above attributes are updated to reflect the desampling.
For example, if a source file has a channel spacing of 10m and it is
spatially desampled to only include every fifth channel, the desampled
file will report a channel spacing of 50m.

## Raw Source-File Metadata

Depending on the raw source files from which the processed file is made,
additional metadata may be present on the desampled file.  This metadata is
stored in another dataset at the root level, named `Acquisition_origin`.
This dataset is empty, and exists only as a placeholder for this metadata.

Metadata is only taken from the first input file being used to generate the
desampled file, and it doesn't include all raw-file metadata.

*   For PRODML (e.g. OptaSense) data files, any attribute/value pairs on the
    HDF5 `/Acquisition/Custom` group will be copied as attributes onto this
    dataset.  Note that datasets and other objects under this group are not
    copied.  Also, other custom data and metadata in the PRODML file, such as
    at the path `/Acquisition/Raw[0]/Custom`, will not be included.

    If gauge length is not available as an attribute on the `/Data` dataset,
    it may be an attribute on the `/Acquisition_origin` placeholder, name
    `GaugeLength`.

    Similarly, the laser pulse-rate is likely available on `/Acquisition_origin`
    under the attribute `PulseRate`.

*   For ASN data files, non-array metadata is copied as attributes onto this
    dataset.

## Event Metadata

If a processed file was generated by extracting information for a seismic
event like an earthquake, the file will contain another empty dataset
called `Event_info`.  This dataset is a placeholder for a large amount of
event metadata, including the following:

*   `resource_id` is the QuakeML URI for the event
*   `source` is the source-catalog of the event (TODO:  list)
*   `event_id` is the catalog ID of the event
*   `version` is the version of the event in the catalog

*   `begin_time` is an ISO8601-format UTC date/time string of the first
    sample in the file (should match `startTime` value on `/Data`)
*   `end_time` is an ISO8601-format UTC date/time string of the last sample
    in the file (should match `endTime` value on `/Data`)

*   `event_time` is an ISO8601-format UTC date/time string of when the
    event occurs in the data file
*   `event_time_index` is the sample-index in the file corresponding to when
    the event occurred.  Note that this may be negative.

*   `magnitude` is the event's magnitude
*   `magnitude_type` is the type of the magnitude

*   `latitude` is the event's latitude
*   `longitude` is the event's longitude

*   `depth_km` is the depth of the event in kilometers (events with a catalog
    depth < 0 will have their depth clamped to 0)
*   `distance_km` is the distance of the event from the "center" of the DAS
    array
*   `detectable_amplitude` is a DAS array-specific value recording the
    minimum event amplitude detectable on the array
*   `distance_threshold` is the maximum distance of an event that can be
    detected on the DAS array
*   `mean_site_term_P`
*   `mean_site_term_S`
*   `time_before` is the number of seconds before the event-start used to
    compute how much DAS data to include
*   `time_after` is the number of seconds after the event-start used to
    compute how much DAS data to include

## ZFP Compression

Processed data may also be compressed with the [ZFP library][zfp].  If this
is the case then the `ZFPtolerance` attribute will be set on the `Data`
dataset.  Its value is the error tolerance used to compress the data.

**Note that if the data is ZFP-compressed then the `/Data` dataset will be an
array of bytes that must be passed through `pyzfp.decompress()` to convert
back into a 2D array of data.**  It cannot be used as-is.  See the tutorial
for more details about how to access the data.

**Event data will not be ZFP-compressed.**

# "Event Files" (older)

Previously, extracted DAS event data used a different file format simply
called "event files."  These files are also HDF5 files, but with a different
schema from the processed event files described above.  Efforts have been
made to create a unified file format for both regular DAS data and event
data, but older files may follow the schema described in this section.

Note also that the older event file format includes much less information
about both the event and the DAS data, so be forewarned.

## The `data` Dataset and Attributes

The DAS data is held in a dataset named `data` at the root level of the file.
This is a 2D dataset where one dimension is the spatial dimension (channels)
and the other is the temporal dimension (samples).  The spatial dimension
is usually first, but file-readers may want to compare the dataset's shape to
the expected number of channels and samples to be sure.

This dataset also defines a number of attributes:

*   `begin_time` is an ISO8601-format UTC date/time string of the first
    sample in the file
*   `end_time` is an ISO8601-format UTC date/time string that is
    _one sample past_ the last sample in the file

*   `unit` is an optional string attribute specifying the units of the data

*   `dt_s` is the sample period in seconds
*   `dx_m` is the channel spacing in meters

>   Note that a number of attributes in the processed format are not present
>   here, such as `fs` (sample-rate), `nt` (number of samples), `nCh` (number
>   of channels), etc.  These must be inferred from other sources.

## Event Metadata

The `data` dataset will also include some attributes describing metadata
about the event:

*   `source` is the source-catalog of the event
*   `event_id` is the catalog ID of the event

*   `begin_time` is an ISO8601-format UTC date/time string of the first
    sample in the file (should match `startTime` value on `/Data`)
*   `end_time` is an ISO8601-format UTC date/time string of the last sample
    in the file (should match `endTime` value on `/Data`)

*   `event_time` is an ISO8601-format UTC date/time string of when the
    event occurs in the data file
*   `event_time_index` is the sample-index in the file corresponding to when
    the event occurred.  Note that this may be negative.

*   `magnitude` is the event's magnitude
*   `magnitude_type` is the type of the magnitude

*   `latitude` is the event's latitude
*   `longitude` is the event's longitude

*   `depth_km` is the depth of the event in kilometers (events with a catalog
    depth < 0 will have their depth clamped to 0)
*   `distance_km` is the distance of the event from the "center" of the DAS
    array
*   `detectable_amplitude` is a DAS array-specific value recording the
    minimum event amplitude detectable on the array
*   `distance_threshold` is the maximum distance of an event that can be
    detected on the DAS array
*   `time_before` is the number of seconds before the event-start used to
    compute how much DAS data to include
*   `time_after` is the number of seconds after the event-start used to
    compute how much DAS data to include

>   Note that the event version is not captured in this format.
